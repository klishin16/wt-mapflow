# Проверка каталога карт

Дата сверки: 2026-11-08. Проверены опубликованные исходники; текущие изображения
всех карт из установленной игры не снимались. Поэтому результат — сверка каталога
с источниками, а не подтверждение совместимости всех хешей с текущей версией War Thunder.

## aHash: PowerBroker2/WarThunder

Источник: [WarThunder/maps.py](https://github.com/PowerBroker2/WarThunder/blob/master/WarThunder/maps.py).
Исходный проектный каталог содержал 60 хешей для 57 уникальных названий.
Опубликованный каталог источника содержит 57 хешей для 54 названий;
53 ключа совпадают с проектом. Найдены четыре отсутствовавших варианта:

| Карта в проекте | Дополнительный хеш из источника |
| --- | --- |
| EasternEurope | `fe7e73f380070001` |
| Finland | `fffe1808081f1f3f` |
| AdvanceToTheRhine | `0cccfc7e7f7efc18` |
| MiddleEast | `fcfefdff7e380001` |

Все четыре добавлены как альтернативные эталоны. Названия проекта сохранены,
чтобы не менять ключи сохранённых позиций и запросов Ratline. Теперь в каталоге
64 хеша для прежних 57 названий.

Семь прежних проектных ключей отсутствуют в источнике: четыре других варианта
этих карт и записи Polygon, GoldenQuarry, IberianCastle. Они оставлены для совместимости,
но независимо не подтверждены. Старые изображения могут соответствовать только
одному варианту карты или уже изменённой версии локации.

## Более новый каталог dHash

[ElBartt/WarThunder-Plotter](https://github.com/ElBartt/WarThunder-Plotter/blob/main/map_hashes.py)
содержит отдельные группы наземных, авиационных и смешанных карт, в том числе
Abandoned Town, Aral Sea и Breslau, которых нет в нашем историческом списке названий.
Следовательно, наш список не покрывает все карты из других публичных каталогов.

Его [capture.py](https://github.com/ElBartt/WarThunder-Plotter/blob/main/capture.py)
вычисляет dHash по различиям соседних пикселей. Эти значения нельзя вставить
в таблицу 64-битного aHash: алгоритмы и длины хешей различаются. Новые dHash
не добавлялись под видом обновлённых aHash. Для включения такого источника нужны
отдельный алгоритм, соответствия названий Ratline и проверка на игровых изображениях.

## Совместимость и принятие решения

Современная [imagehash](https://github.com/JohannesBuchner/imagehash/blob/master/imagehash/__init__.py)
сериализует биты от старшего к младшему, а проектный `toHexString()` — наоборот
в каждом байте. У библиотеки также был исторический формат `old_hex_to_hash`.
Одного сравнения кода недостаточно, чтобы установить формат всех старых эталонов.

Распознавание теперь сравнивает четыре варианта: прежнюю обработку и обработку
с переводом в серый до уменьшения, каждый в MSB и LSB порядке. Это варианты
совместимости; Pica не гарантирует побитовое совпадение с Pillow. Прежний хеш
остаётся основой `custom-*` и ручных привязок.

Расстояние считается по битам, а не по hex-символам. Для автоматического решения
допускаются до 3 отличий из 64 и отрыв от другого названия минимум на 2 бита.
Эталоны одного названия объединяются в одного кандидата. Одноцветные изображения
не распознаются автоматически. Неоднозначное совпадение оставляется неизвестным.
Пороги консервативные, но ещё не откалиброваны на коллекции текущих игровых кадров.

## Проверка в игре

1. Открыть «Определение карты → Диагностика хешей» в реальном бою.
2. Сравнить действительное название с выбранным и пятью ближайшими кандидатами.
3. Проверить отдельно наземную и авиационную карту, а также обрезанные варианты.
4. Если совпадения нет, выбрать название Ratline и нажать «Применить и запомнить».
   Привязка хранится в localStorage `wt-rat.map-bindings.v1`; «Автоопределение» удаляет её.
5. Новые эталоны добавлять только вместе с подтверждённым названием и вариантом
   изображения. Само название не гарантирует совмещение границ с Ratline.
